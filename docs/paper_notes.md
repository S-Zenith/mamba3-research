# Mamba 论文笔记与本项目边界

## 先说结论

本项目做的是“小规模性能 demo”，不是完整论文复现。完整论文复现通常需要大规模数据集、长时间训练、严格的超参数和多张 GPU。本项目更关注：同一台机器、同一组小输入下，不同 Mamba block 的前向运行时间和算子级开销。

## Mamba 是什么

Mamba 属于选择性状态空间模型。你可以把它粗略理解成一种处理序列数据的神经网络模块。传统 Transformer 常用注意力机制，序列越长，注意力计算和显存压力通常越大。Mamba 试图用状态空间结构和硬件友好的扫描算法高效处理长序列。

## Mamba-2 是什么

Mamba-2 是后续版本，论文里通常强调更结构化的状态空间对偶性，以及更适合现代硬件的实现方式。对用户来说，可以先把它看成一个新的 Mamba block 变体：接口类似，但内部算子和性能特征可能不同。

## Mamba-3 的说明

本目录里有 `mamba3.pdf`，但 Python 生态里是否存在能直接 `pip install` 的官方 Mamba-3 block，需要以实际可导入代码为准。本项目不会伪造“官方 Mamba-3 性能”。如果没有可用官方实现，报告会把它标成不可用。

## 为什么本项目用随机输入

性能 profiling 不一定需要真实数据集。为了观察 block 本身的前向时间和显存，我们可以构造形状相同的随机张量。这样能避免数据下载、预处理和训练循环干扰。

## 为什么要 warmup

GPU 第一次运行时可能有 CUDA 初始化、kernel 加载或编译开销。warmup 是先运行几次但不计入最终结果，让正式计时更稳定。

## 为什么说“算子级”而不是“硬件级”

本项目默认用 PyTorch profiler。它能告诉我们 PyTorch 看到的算子、CPU/CUDA 时间和显存变化。它不是 Nsight Compute 那种硬件级分析工具，所以不能精确给出每条内存指令或真实带宽瓶颈。
